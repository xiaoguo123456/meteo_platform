# 现货出清电价数据源

2026-10-27 通过微信小程序抓包找到并实测。接口属于第三方小程序（AppID `wxda1c8f9611eb040a`）的私有后端，没有公开文档，字段和规则随时可能变化，只适合低频拉取。

目前有两个接口：

| 接口 | 用途 |
|---|---|
| 出清电价明细 | 单省一天的 96 点日前、实时价曲线 |
| 各省均价排行 | 全国各省日均价对比，附新能源机制电价 |

两个接口的鉴权方式相同，都拿不到历史数据，要逐日积累只能每天拉取后自存。

## 出清电价明细

### 请求

`POST https://elecheck.aienertech.cn/electricCheckApi/queryData/clearPrice/detail`

请求头：

| 头 | 值 |
|---|---|
| `Authorization` | 小程序登录后下发的 JWT，不带 `Bearer` 前缀 |
| `Content-Type` | `application/json` |

实测不校验 `User-Agent`、`Referer`、`xweb_xhr`，只要带 `Authorization` 即可。token 是账号凭证，放在 `.env`，不要写进代码或文档。

token 会过期。JWT 里没有 `exp` 字段，但服务端会自行判定，实测约 11 小时内失效（9:31 签发，20:31 已失效），过期后返回 `{"code":401,"msg":"Token已过期，请重新登录"}`。

新 token 由登录接口 `GET /electricCheckApi/user/getPhoneNumber?code=...&openid=...` 下发，返回体 `data.token`。其中 `code` 是微信手机号授权码，只能在微信内由用户点击授权生成，一次性且几分钟内过期，无法在脚本里自动续期。目前只能重新打开小程序登录后抓包，手动更新 `.env`。

请求体：

```json
{"dateType": 0, "areaCode": "320000000000"}
```

- `areaCode`：12 位行政区划代码，省级为“省代码 + 10 个 0”。
- `dateType`：数据范围，见下表。请求里没有日期参数，查不了指定日期。

| dateType | 结果 | 含义 |
|---|---|---|
| `0` | 支持 | 当天。实时价含义见下方说明 |
| `1` | 400 “出清价格不支持该dateType” | 不支持 |
| `2` | 支持 | 近 7 天平均 |
| `3` | 支持 | 近 30 天平均 |
| `4` | 支持 | 约 180 天平均 |
| `5`、`-1` | 400 “dateType不能为空或不支持” | 不存在 |

`dateType=0` 为当天的依据：6 个省的 96 点日前价取平均后，与各省均价排行接口 `infoDate` 为当天时的 `averagePrice` 完全一致，与前一天不一致。

当天 12:37 拉取时，江苏实时价已有到 16:30 的值，尚未到达的时段不可能有正式实时出清结果。因此当天的实时价可能是预出清或预估值，之后会被正式值替换，具体含义未确认。

`2`–`4` 的天数由返回值反推：江苏原始价格为 1 位小数，平均值乘以天数再乘 10 应为整数，满足条件的最小天数分别是 7、30、180。`4` 也可能是近一年但有缺数。

### 返回

```json
{
  "code": 200,
  "message": "OK",
  "data": [
    {"time96": "00:15", "avgDayAheadPrice": "423.5", "avgRealTimePrice": 430.3}
  ]
}
```

| 字段 | 含义 | 注意 |
|---|---|---|
| `time96` | 时段时刻 | 名字叫 96，但点数随省份变化 |
| `avgDayAheadPrice` | 日前出清均价，元/MWh | 字符串 |
| `avgRealTimePrice` | 实时出清均价，元/MWh | 数字，未出清或未接入时为 `null` |

出错时 HTTP 状态仍为 200，`code` 为 400，`data` 为 `{}`，原因在 `message`。

### 各省实测（dateType=0，2026-10-27 22 点拉取）

均价排行返回的 29 个区域中，28 个有明细曲线，只有蒙西返回空数组。

| 时刻口径 | 点数 | 省份 |
|---|---|---|
| 时段结束，00:15–24:00 | 96 | 河北南网、山西、蒙东、辽宁、吉林、黑龙江、上海、江苏、安徽、福建、江西、四川、陕西、甘肃、青海、新疆 |
| 时段结束，00:30–24:00 | 48 | 浙江 |
| 时段结束，01:00–24:00 | 24 | 山东、河南、湖北、湖南、宁夏 |
| **时段开始**，00:00–23:00 | 24 | 广东、广西、海南、贵州、云南（南方电网区域） |
| 时段结束，5 分钟与 15 分钟混合 | 216 | 重庆 |

- 重庆：有实时价的时段 5 分钟一个点（00:05 起），之后 15 分钟一个点；5 分钟点上的日前价是所在 15 分钟时段的值重复。
- 实时价：只有山西、辽宁、江苏、福建、重庆、四川、甘肃、青海 8 个省有值，其余为 `null`。
- 四川：日前价全为空，只有实时价。
- 时刻口径是按时刻范围推断的，接口本身不说明。

山东日前价出现过 -60，属于正常的负电价，不是解析错误。

## 各省均价排行

### 请求

`POST https://elecheck.aienertech.cn/electricCheckApi/home/provinceAveragePriceBarChartData`

请求头同出清电价明细。请求体：

```json
{"type": "day_ahead", "dateType": 1, "sort": 2, "infoDate": "2026-10-26"}
```

| 参数 | 含义 |
|---|---|
| `type` | `day_ahead` 日前价，`real_time` 实时价 |
| `dateType` | `1` 单日（按 `infoDate`）；`2`、`3`、`4` 为多日平均，推测与出清电价明细相同（7、30、180 天），未验证；`0` 返回 400 “首页不支持该dateType” |
| `sort` | `1` 按均价升序，`2` 降序 |
| `infoDate` | 日前价只允许 D-1～D+1，超出返回 400 “info_date超出允许范围（d-1~d+1）”；实时价只允许 D-3～D-1，提示为 “（d-3~d-1）”；不传时默认前一天 |

### 返回

```json
{
  "code": 200,
  "message": "OK",
  "data": [
    {
      "areaCode": "370000000000",
      "areaName": "山东",
      "averagePrice": 448.2189583333333,
      "electricityPrice": 225.0,
      "windElectricityPrice": 319.0,
      "marketReferencePrice": 389.1901916666667
    }
  ]
}
```

| 字段 | 含义 | 注意 |
|---|---|---|
| `areaCode` / `areaName` | 地区 | 有电网分区代码：河北南网 `130000000001`、蒙东 `150000000001`、蒙西 `150000000000` |
| `averagePrice` | 所选 `type` 的全天均价，元/MWh | 随 `type`、`dateType`、`infoDate` 变化；未出清时为 `null` |
| `electricityPrice` | 光伏机制电价，元/MWh | 不随日期变化。山东光伏 225、风电 319，与山东 2025 年机制电价竞价结果一致，据此推断 |
| `windElectricityPrice` | 风电机制电价，元/MWh | 同上 |
| `marketReferencePrice` | 市场参考价 | 含义未确认；随 `dateType` 变化，数值接近均价 |

数值有浮点误差（如 `224.99999403953552`、`392.90000000000003`），入库前按需四舍五入。

### 实测（2026-10-27）

- 日前价返回 27 个区域，不含四川、蒙西。
- 实时价返回 29 个区域，多四川、蒙西；山东、安徽、广东、广西、云南、湖南的实时均价为 `null`。
- `infoDate` 为当天时日前价已全部发布；为次日时只有江苏、山西有值，各省日前价发布时间不同。

## 接入注意

- 多省对比前先统一时刻口径：南方电网五省为时段开始，其余为时段结束；`24:00` 需转成次日 `00:00`。点间隔不一定均匀（重庆），时段长度要按相邻时刻算。
- 出清电价明细的两个价格字段类型不同，入库前统一转成浮点数。
- 明细接口只能查当天，过了当天就拿不到这一天的曲线。拉取要放在当天深夜，实时价才最接近最终值。
- 要逐日历史只能每天拉取自存：明细在当天深夜拉 `dateType=0`，均价排行可在次日拉 `dateType=1` 的前一天。
- 两个接口数据同源：均价排行的日前 `averagePrice` 等于明细曲线的平均值（单日和 7 天平均均已核对）。实时价尚未核对。
- token 约半天失效且不能自动续期，定时任务需要在 401 时告警，提醒人工更新 token。
- 本机设置了 `HTTP_PROXY` 时，代理不可用会导致请求直接失败；脚本里可显式绕过代理（如 `curl --noproxy '*'`、`httpx` 的 `trust_env=False`）。

## 本站接入

页面入口为 `/#price`。后端代码在 `backend/app/price/`，随 API 进程启动后台拉取任务，不另起容器。

### 拉取节奏

拉取时间不固定，避免按整点规律请求：

- 白天每次间隔随机 40–80 分钟；凌晨 1–6 点放宽到 90–150 分钟。
- 每天 23:25–23:55 之间随机补拉一次，让当天实时价尽量接近最终值。
- 0:00–0:20 不拉，因为上游“当天”在跨日时何时切换不确定。

请求分两种轮次，顺序每轮打乱，请求之间随机等 0.8–2.5 秒：

| 轮次 | 什么时候 | 明细 | 均价排行 | 请求数 / 耗时 |
|---|---|---|---|---|
| 完整 | 当天第一次成功拉取、晚间 23:25–23:55 那次 | 全部区域 | 日前价前一天、当天、次日；实时价前 3 天 | 约 35 个 / 1 分钟 |
| 普通 | 其余时间 | 只拉当天还没有曲线、或曲线里有实时价的省份（目前 8 个） | 当天、次日日前价；前一天实时价 | 约 11 个 / 20 秒 |

日前曲线一天只发布一次，入库后不再重复请求；返回空数组的区域（蒙西）当天也只在完整轮次重试。token 断档恢复后的第一次拉取就是完整轮次，实时均价能补回前 3 天。

区域列表是代码里的 29 个区域，加上近 7 天均价排行里出现的新区域，新增省份不用改代码。

API 重启时，如果距上次拉取不到 30 分钟，就跳过这一轮。

### 存储

数据存在 SQLite 数据库 `data/price/price.sqlite` 里，与资讯库分开：

| 表 | 主键 | 内容 |
|---|---|---|
| `clear_price_curve` | 省份、日期、`slot_end` | 分时曲线。`slot_end` 是时段结束时刻距当日 0 点的分钟数（15–1440）；口径按返回时刻自动判断：出现 `00:00` 视为时段开始，时段结束取下一个点的时刻（最后一个点到 24:00），目前南方电网五省如此；点间隔不均匀时（重庆）每个时段长度单独计算；原始时刻保留在 `raw_time` |
| `province_average` | 日期、价格类型、地区 | 各省日均价和机制电价 |
| `fetch_runs` | 自增 | 每轮拉取的结果和错误，保留最近 500 条 |
| `state` | key | token 状态、下次拉取时间 |

- 明细每次拉取都会整天替换：同一天以最后一次拉取为准，避免旧的预出清值残留在后面的时段。
- 均价按主键覆盖写入，但新值为 `null` 时不覆盖已有的值。
- 价格统一存成浮点数，保留 2 位小数。
- 备份用 SQLite backup API，不要直接复制正在写入的数据库文件。

### token

token 存在 `data/price/token.json` 里，文件权限 600，不写入数据库，接口也不返回。文件不存在时读环境变量 `PRICE_TOKEN`。

- `GET /api/price/status`：返回 token 状态和相关时间。状态有 `valid`、`expired`、`missing`、`error`、`unchecked` 几种；时间包括签发时间、预计失效时间（签发后 11 小时）、最近数据时间和下次拉取时间。
- `POST /api/price/token`，请求体为 `{"token": "..."}`：先用新 token 真实请求一次上游，成功才保存，并立即在后台拉取一轮。返回 `{"ok": true/false, "message": "..."}`。同一进程 5 秒内只允许尝试一次，超出返回 429。
- 管理密钥：设置了环境变量 `PRICE_ADMIN_KEY`，或存在 `data/price/admin_key` 文件时，请求头必须带 `X-Admin-Key`，否则返回 403。生产环境建议用文件方式：`deploy/.env` 每次部署都会被覆盖，`data/` 目录则会保留。

```bash
curl -X POST https://站点域名/api/price/token \
  -H 'Content-Type: application/json' -H 'X-Admin-Key: 管理密钥' \
  -d '{"token":"抓包得到的 JWT"}'
```

### 读取接口

- `GET /api/price/dates`：列出已有数据的日期，并标明这一天有没有曲线、有没有均价。
- `GET /api/price/day?date=YYYY-MM-DD`：返回这一天各省的曲线和各省均价。不传日期时，返回有曲线数据的最近一天。
